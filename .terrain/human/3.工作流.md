# 3. 工作流

> 面向想要理解"MNS 运行时发生了什么"的读者。MNS 的一切行为都是命令行触发的同步流水线，本文拆解五大核心工作流，并讨论并发模型与错误处理策略。

## 工作流全景

MNS 的核心工作流可以比喻成一家"晚间报盘公司"的生产线：**原材料（市场数据）从外部市场进来 → 档案室（SQLite）归档 → 分析师（策略）给出建议 → 秘书（报告）排版出厂**。回测则像"审计部门"——用历史档案抽查分析师的建议在过去的表现，确保建议不是拍脑袋。

整体是**同步顺序执行**的命令行流水线：一次命令 = 一个完整闭环，没有常驻进程、没有后台任务、没有事件驱动。以下是五大工作流的速览：

| 工作流 | 触发命令 | 入口点 | 主要协作模块 |
|--------|---------|--------|------------|
| 每日报告生成 | `mns report` | cmd_report（src/main.rs:348） | 情绪与行情 → 数据持久化 → 策略核心 → 报告生成 |
| 价格批量更新 | `mns update-prices` | cmd_update_prices（src/main.rs:772） | 数据持久化 → 情绪与行情 |
| 交易记录 | `mns buy` / `mns sell` | cmd_buy / cmd_sell（src/main.rs:270/281） | 数据持久化 |
| 策略回测 | `mns backtest` | cmd_backtest（src/main.rs:437） | 回测引擎 → 绩效指标 → 策略核心 |
| 样本外验证 | `mns backtest validate` | cmd_backtest_validate（src/main.rs:533） | 回测引擎 → 绩效指标 |

## 工作流 1：每日报告生成（核心价值流）

这是 MNS 的"拳头产品"，把用户从"今天该不该买/卖？"的情绪困境中解放出来。市场波动时，人脑会被恐惧和贪婪劫持，而这个流程用固定的规则链替代情绪决策。

```mermaid
sequenceDiagram
    participant U as 用户
    participant M as cmd_report<br/>(main.rs)
    participant S as 情绪与行情<br/>(sentiment)
    participant D as 数据持久化<br/>(db)
    participant ST as 策略核心<br/>(strategy)
    participant R as 报告生成<br/>(report)

    U->>M: mns report
    M->>S: fetch_fear_greed_data(url)
    S-->>M: FearGreedData (score + 历史)
    M->>D: save_fear_greed_snapshot(...)
    M->>D: get_cash_balance() / list_positions()
    D-->>M: cash / positions
    M->>ST: check_risk_warnings(config, score, positions)
    ST-->>M: risk_warnings
    M->>ST: calculate_rebalance_plan(config, score, cash, positions, today)
    ST-->>M: RebalancePlan
    M->>R: generate_report(...)
    R-->>M: report 文本
    M->>R: save_report(config, report)
    R-->>U: 终端打印 + reports/{date}.txt
```

**执行步骤**：

1. **拉取 CNN 恐贪指数**（`sentiment::fetch_fear_greed_data`，src/sentiment.rs:57）——系统先感知市场情绪温度；内置 3 次重试与 418 反爬处理。
2. **保存情绪快照**（`db.save_fear_greed_snapshot`，src/db.rs:373）——同一天只保留最新快照，形成可回溯的历史序列。
3. **计算风险警告**（`strategy::check_risk_warnings`，src/strategy.rs:292）——找出浮亏超 20% 的持仓，按情绪环境给出差异化建议（恐慌环境→可能加仓机会；贪婪环境→紧急审视）。
4. **计算调仓计划**（`strategy::calculate_rebalance_plan`，src/strategy.rs:406）——核心决策：目标仓位 vs 当前仓位，偏离超带宽才动作，卖出先于买入。
5. **渲染报告并落盘**（`report::generate_report` + `report::save_report`，src/report.rs:23/298）——终端展示 + `reports/{date}.txt` 存档。

**输出**：完整报告，包含市场情绪、账户概览、持仓明细、调仓计划、净操作指引、风险警告、目标仓位预案、信号口径 8 个信息块。

从时序图能读出的关键模式：**数据单向流动**——外部数据进来先归档（snapshot），决策只读已归档数据，报告只消费决策结果。每一步的输出类型明确（`FearGreedData` → `RebalancePlan` → 文本），没有隐藏的共享状态。

## 工作流 2：价格批量更新

价格是决策的燃料——没有现价，就无法计算偏离、无法给出调仓建议。这个流程解决"我持仓的几十个基金/ETF 今天值多少钱"的批量获取问题。

**执行步骤**：

1. **列出全部持仓**（`db.list_positions`，src/db.rs:121）。
2. **逐个获取价格**（`quote::update_all_prices`，src/quote.rs:197）——按代码特征路由：6 位纯数字 → 天天基金（东财移动端优先，JSONP 兜底）；字母 → Yahoo Finance。
3. **单个资产失败只打 eprintln 警告并跳过**，不中断整个流程（src/quote.rs:218-231）——体现"局部失败不应导致全局中断"的降级理念。
4. **成功更新的资产写回数据库**（`db.update_price`，src/db.rs:287）——同时调用 `record_price`（src/db.rs:303）累积价格历史，为趋势锚（价格 vs 12 月均线）积累数据。

**输出**：更新结果表格（代码/名称/原价/新价/来源）+ 数据库同步。

## 工作流 3：交易记录（买入/卖出）

**执行步骤**：

1. **校验参数**（份额/价格为正；卖出不超持有量）。
2. **打开 SQLite 事务**（`unchecked_transaction`，src/db.rs:210/263）——买入：更新持仓份额与加权平均成本 + 扣减现金 + 写入 buy 交易流水；卖出：更新持仓 + 回补现金 + 写入 sell 流水。**三步在同一事务内**，保证不出现"钱扣了持仓没加"这类账目不一致。
3. **提交事务**。

**输出**：确认信息 + 数据库一致性变更。这个流程虽然简单，却是整个系统数据可信度的地基——所有账目变更要么全部生效、要么全部回滚。

## 工作流 4：策略回测

```mermaid
sequenceDiagram
    participant M as cmd_backtest<br/>(main.rs)
    participant B as 回测引擎<br/>(backtest.rs)
    participant MT as 绩效指标<br/>(metrics.rs)

    M->>B: load_main()
    B-->>M: Vec<MonthRow>
    M->>B: run(config, bt_config, signal, engine, rows)
    loop 逐月
        B->>B: 现金计息 / 年度注资
        B->>B: rebalance_to_weights(先卖后买)
        B->>B: 记账 Monthly
    end
    B->>MT: xirr(flows) / risk_metrics(returns)
    MT-->>B: XIRR / RiskMetrics
    B-->>M: BacktestResult
    M->>B: print_report(r) / print_comparison(results)
```

**执行步骤**：

1. **加载编译期嵌入的真实数据**（`backtest::load_main`，src/backtest.rs:85）——2016-2025 月度全收益序列（人民币计价、含分红），113 个月。
2. **平滑情绪信号**（`smooth_fgi`，src/backtest.rs:360）——3 个月移动平均，避免用周级噪声驱动年级组合。
3. **计算目标权重序列**（`compute_target_risk_weights`，src/backtest.rs:322）——按锚点类型（情绪锚/趋势锚）映射。
4. **逐月模拟**（`run`，src/backtest.rs:557）——月循环：现金计息 → 年度注资 → 调仓（先卖后买）→ 记账。
5. **指标统计**（`metrics::xirr` / `metrics::risk_metrics`，src/metrics.rs:18/140）——XIRR、最大回撤、Sharpe、Sortino、Calmar。
6. **输出对比**（`print_report` / `print_comparison`，src/backtest.rs:864/1018）——默认跑 5 个变体（趋势锚/情绪锚/旧框架/买入持有+再平衡/买入持有）在同一数据与成本模型下对比。

**输出**：逐策略报告 + 策略对比表。

关键交互模式：回测引擎与绩效指标是**纯函数式调用**——`run()` 输入配置+数据返回结果结构体，无副作用，天然可复现、可测试（src/backtest.rs 有 15+ 个单元测试验证引擎行为）。

## 工作流 5：样本外验证

`mns backtest validate` 是对"回测结果不是过拟合"这一疑问的系统性回答，分四步：

**执行步骤**：

1. **Walk-forward 切分**：前 60% 数据调参，后 40% 验证（src/main.rs:549）。
2. **网格搜索**：3 个仓位缩放 × 4 个偏离带，在样本内挑 Calmar 最优（src/main.rs:568-586）。
3. **样本外测试**：最优参数 vs 默认配置 vs 趋势锚 vs 买入持有（src/main.rs:619-628）；若最优参数样本外劣于默认，明确提示"典型过拟合信号"（src/main.rs:649-651）。
4. **分块 bootstrap**：2000 次重采样，给出年化/回撤的 P5/P50/P95 分布（src/main.rs:653-688），并输出 holdout 区块（用从未参与调参的独立数据段复核，src/main.rs:690-718）。

**输出**：调参网格表、样本外对比表、bootstrap 分布表、holdout 表 + 口径与局限说明。

这个流程体现了 MNS 对回测的审慎：**"回测跑得好看"与"策略真的有效"是两回事**——网格搜索挑出的最优参数可能只是拟合了历史噪声，所以必须用样本外数据 + 分布检验 + 独立 holdout 三重验证才敢下结论。

## 并发/异步模型

MNS 的并发策略是"**稳优先而非快优先**"。它是单用户 CLI，绝大多数操作是同步的 SQLite 读写与同步的顺序遍历，根本不需要并发。唯一的异步点是网络请求（拉取恐贪指数、批量价格、市场指数），用 `#[tokio::main]`（src/main.rs:19）+ `async fn` + reqwest 处理。但即使在这里，也是**串行 await 而非并发 fetch**——例如 `update_all_prices` 逐个资产顺序请求（src/quote.rs:197-235）。

这种设计放弃了批量并发的速度，换来了三样东西：

- **对免费第三方 API 的友好**——不会并发打爆反爬；
- **实现简单**——没有并发同步的复杂性；
- **错误隔离清晰**——每个请求独立成功或失败，互不干扰。

对个人工具而言，等待几十个请求多花几秒，远不如稳定重要。没有共享可变状态、没有锁、没有通道——Rust 的所有权模型在这里自然适配了"单线程流水线"。

## 错误处理策略

核心理念是"**局部失败不应导致全局中断，关键数据缺失必须显式失败**"，分层来看：

| 层级 | 策略 | 示例 |
|------|------|------|
| 网络层 | 重试 + 降级 | CNN API 最多重试 3 次、间隔 500ms（src/sentiment.rs:62-77）；东财失败降级到天天基金 JSONP（src/quote.rs:124-129） |
| 批量操作 | 逐项隔离 | 单个资产价格失败只打 `eprintln` 警告（src/quote.rs:218-231）；市场指数获取失败汇总成错误表，不全军覆没（src/market.rs:57-83） |
| 业务规则 | 前置校验 | 买入前查现金余额（src/db.rs:187-190）、卖出前查超持（src/db.rs:245-250）、配置写盘前 `validate()`（src/main.rs:142） |
| 数据完整性 | 事务保障 | 买卖操作在单个 SQLite 事务内完成持仓+现金+流水三写（src/db.rs:208-231） |
| 用户输入 | 友好报错 | anyhow + `with_context` 给出中文错误上下文（如"打开数据库失败: {path}"，src/db.rs:18） |
