# 数据模型

> 源码：`src/models.rs`

## 模块职责

数据模型模块是 MNS 的"契约"——定义了系统流转的三种核心数据结构：`Position`（持仓）、`Transaction`（交易）、`FearGreedSnapshot`（情绪快照）。它是所有模块间传参的"共同语言"，纯数据、无 IO、无外部依赖（仅 chrono）。

它解决的核心问题：**模块之间用什么形状传递数据**。正因为所有模块都消费同一套结构，`db.rs` 存进去的、`strategy.rs` 算的、`report.rs` 渲染的都是同一形状的数据，杜绝了"层层转换导致的信息损耗"。

## 核心功能

| 功能 | 位置 | 说明 |
|------|------|------|
| 持仓模型 | src/models.rs:5 | 9 个字段承载持仓状态 |
| 年化收益计算 | src/models.rs:41 | 正收益复利、负收益简单年化，支持最小持仓天数门槛 |
| 市值降级估算 | src/models.rs:25 | 无现价时用成本价估算市值 |
| 交易模型 | src/models.rs:79 | 类型/份额/价格/金额/日期/备注 |
| 情绪快照模型 | src/models.rs:92 | 分数/区间/4 个历史参照/抓取时间 |

### 收益计算的工程细节

`annualized_return_with_min_days`（src/models.rs:41）对正负收益用两套公式：正收益用复利 `(current/cost)^(1/years)`，负收益用简单年化——避免 `(0.95)^12-1 ≈ -46%` 的亏损被复利公式过度放大。同时支持最小持仓天数门槛（持仓不足门槛不返回年化，避免短期收益失真）。

### "无现价"的降级策略

`current_price` 为 `Option<f64>`，缺失时用成本价估算市值（`market_value_or_cost`，src/models.rs:25-29）——把"数据缺失"显式建模进类型系统，而非用 0 或空字符串这种隐式方案。总资产这类"不可缺失"场景因此永远有值。

## 跨模块协作

| 交互模块 | 方向 | 说明 |
|---------|------|------|
| 数据持久化 | 被依赖 | 行→结构映射，db.rs 查询结果填充这些结构 |
| 策略核心 | 被依赖 | 调仓计算消费 `Position` |
| 报告生成 | 被依赖 | 持仓明细渲染 |
| 回测引擎 | 被依赖 | `Leg::to_position`（src/backtest.rs:175）转换供 Legacy 引擎消费 |

**协作场景**：每日报告中 `Position` 是数据载体——db 读出、策略算、报告渲染，全程同一个类型，`annualized_return_with_min_days` 在两处被调用（src/main.rs:208, src/report.rs:106）保证年化口径一致。回测流程中 `Leg::to_position`（src/backtest.rs:175）把 FIFO 持仓转成 `Position`，让 Legacy 引擎的买卖建议函数直接消费——**数据模型的统一让"实盘与回测复用决策代码"成为可能**。

## 性能考量

纯数据 + 两个 O(1) 计算方法，无性能问题。`Position` 用 `String` 存日期（与 db 的 TEXT 直接对应），避免解析开销；需要日期运算时按需 `parse_from_str`（src/models.rs:47）。

## 实现亮点

- **收益计算的工程细节**（src/models.rs:41-64）：同一收益正负两套公式，避免"亏损组合年化被算成 -46%"的荒谬结果，是数据层对诚实性的又一次落实。
- **"无现价"的降级策略**（src/models.rs:25-29）：用 `Option<f64>` 显式建模数据缺失，而非隐式占位——缺失是状态的一部分，不是错误。
