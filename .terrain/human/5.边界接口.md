# 系统边界接口文档

本文档描述 MNS 的外部调用接口，包括 CLI 命令、外部行情 API、配置参数和其他边界机制。理解边界接口，就是理解"这台机器能怎么被操作、它又怎么与世界对话"。MNS 的边界极其收敛：**对外只有"读"没有"写"**——它从三个公开行情接口读取数据，从不向外部发送任何信息；**对内只有命令行一个入口**——所有功能都以命令形式暴露，没有服务、没有后台进程。这种收敛的边界设计，让工具的行为完全可预期、可审计。

---

## 命令行接口 (CLI)

MNS 通过 `mns <子命令> [参数]` 的形式与用户交互。命令定义于 `src/cli.rs`，分派于 `src/main.rs:23-64`。所有命令都遵循同一执行骨架：加载配置 → 打开数据库 → 执行领域逻辑 → 渲染/落盘。

### 基础命令

#### mns init

**描述**：初始化 `~/.mns/config.toml` 与 `~/.mns/mns.db`。已有数据时交互式确认，防止误覆盖。

**参数**：
| 参数 | 类型 | 是否必须 | 默认值 | 说明 |
|------|------|---------|-------|------|
| `--force` | flag | 否 | 无 | 跳过覆盖确认，强制重新初始化 |

**使用示例**：
```bash
mns init
mns init --force
```

---

#### mns config

**描述**：查看/修改配置。无参显示全部配置；单 key 查值；key+value 改值。改前经过 `validate()` 校验，非法配置拒绝落盘（`src/main.rs:141-143`）。

**参数**：
| 参数 | 类型 | 是否必须 | 默认值 | 说明 |
|------|------|---------|-------|------|
| `key` | string | 否 | 无 | dot-path 配置键，如 `thresholds.fear` |
| `value` | string | 否 | 无 | 要设置的值（与 key 成对出现） |

**使用示例**：
```bash
mns config
mns config thresholds.fear
mns config rebalance.band_pp 6
```

---

#### mns cash set

**描述**：设置现金余额，金额必须为正数。

**参数**：
| 参数 | 类型 | 是否必须 | 默认值 | 说明 |
|------|------|---------|-------|------|
| `amount` | number | 是 | 无 | 现金金额 |

**使用示例**：
```bash
mns cash set 100000
```

---

#### mns portfolio / mns history

**描述**：`portfolio` 查看持仓表格（年化收益着色：达标绿/亏损红，`src/main.rs:209-214`）；`history` 查看交易历史流水。两者均为只读展示，无参数。

**使用示例**：
```bash
mns portfolio
mns history
```

---

### 策略与报告命令

#### mns report

**描述**：生成每日策略报告（市场情绪 → 调仓计划 → 风险警告 → 信号口径），打印并落盘 `reports/YYYY-MM-DD.txt`。恐贪抓取失败时命令中断（`src/main.rs:356`）——没有情绪信号的决策不可信。

**参数**：无。

**使用示例**：
```bash
mns report
```

---

#### mns sentiment

**描述**：查看当日恐贪指数（当前分 + 一周/一月/一年前参照值）。

**参数**：无。

**使用示例**：
```bash
mns sentiment
```

---

#### mns backtest run / validate / params

**描述**：`run` 跑四种策略对比回测；`validate` 做 walk-forward 样本外验证 + bootstrap 收益分布（`src/main.rs:533`）；`params` 打印可调参数帮助。

**参数**：
| 参数 | 类型 | 是否必须 | 默认值 | 含义解读 |
|------|------|---------|-------|---------|
| `--config <path>` | string | 否 | 默认配置 | 用指定配置文件跑回测——不同配置就是不同策略，这是"参数敏感性分析"的入口 |
| `--compare <a,b>` | string | 否 | 无 | 逗号分隔的多个配置对比——同一数据同一成本模型下的公平对照 |

**使用示例**：
```bash
mns backtest run
mns backtest validate
mns backtest params
mns backtest run --config my.toml --compare base.toml,agg.toml
```

### 市场数据命令

#### mns update-prices

**描述**：批量刷新全部持仓价格（国内基金走东财/天天双源，美股/ETF 走 Yahoo），失败单标的跳过（`src/quote.rs:217-231`）。同时更新 `positions.current_price` 与 `price_history`。

**参数**：无。

**使用示例**：
```bash
mns update-prices
```

---

#### mns market / mns market-indices

**描述**：`market` 展示宽基指数表 + 恐贪指数小表（涨绿跌红），并顺带刷新持仓价格（`src/main.rs:834-841`）；`market-indices` 只展示指数涨跌表。

**参数**：无。

**使用示例**：
```bash
mns market
mns market-indices
```

---

#### mns analyze <code> / mns quote <code>

**描述**：`analyze` 查看单标的详细报价；`quote` 查看单标的快照。

**参数**：
| 参数 | 类型 | 是否必须 | 默认值 | 含义解读 |
|------|------|---------|-------|---------|
| `code` | string | 是 | 无 | 资产代码——6 位纯数字走国内基金数据源，字母代码走 Yahoo |

**使用示例**：
```bash
mns analyze 510880
mns quote QQQ
```

---

### 交易记账命令

#### mns buy / mns sell

**描述**：`buy <code> <amount>` 按金额买入记账；`sell <code> <shares>` 按份额卖出记账。两者均为**记账而非真实交易**——系统不会下单，只是记录你的手动操作。

**参数**：
| 参数 | 类型 | 是否必须 | 默认值 | 含义解读 |
|------|------|---------|-------|---------|
| `code` | string | 是 | 无 | 资产代码 |
| `amount`（buy） | number | 是 | 无 | 买入金额——决定份额 = 金额 / 当前价 |
| `shares`（sell） | number | 是 | 无 | 卖出份额——不能超过当前持有 |

**使用示例**：
```bash
mns buy 510880 10000
mns sell 510880 500
```

## 外部行情 API（系统 ↔ 外部世界）

MNS 依赖三个免费公开行情接口。它们全部是只读的 HTTP GET，全部带超时与重试，全部走"失败隔离"路径。下表是这三个数据源的全貌。

| 数据源 | 用途 | 响应格式 | 调用点 | 含义解读 |
|--------|------|---------|--------|---------|
| CNN Fear & Greed API | 恐贪指数（0-100 + 历史参照） | JSON | `src/sentiment.rs:57` | 整个策略的主输入信号——情绪分数直接映射目标仓位 |
| 东方财富移动端 | 国内基金净值（GSZ/NAV） | JSON | `src/quote.rs:32` | 6 位数字代码（基金）的主数据源，优先取估算净值 |
| 天天基金 JSONP | 国内基金净值备份（gsz/dwjz） | JSONP | `src/quote.rs:80` | 东财失败时的自动备份源——双源保障体现"外部不可靠"的悲观假设 |
| Yahoo Finance v8 | 美股/ETF 价格与前收 | JSON | `src/quote.rs:132` | 字母代码（QQQ 等）与指数的数据源 |

**容错约定**：全部为免费公共接口，所有抓取都带超时（10s 请求 / 5s 连接）与浏览器 UA 伪装；国内基金走"主源 → 备份"双源降级（`src/quote.rs:124`）；恐贪抓取在 `cmd_report` 中失败即中断（决策链严格），在 `cmd_market` 中失败仅警告（展示链宽容）。

## 配置结构

MNS 的配置是一个 TOML 文件 `~/.mns/config.toml`，定义于 `src/config.rs`。它不只是参数表，而是**策略语义的载体**——目标仓位曲线、偏离带宽、成本模型都在这一个文件里，任何一处改动都会改变策略行为。

**示例配置**：
```toml
[settings]
annual_goal = 8.0          # 年度收益目标（%）——止盈线的判定基准

[allocation]
us_etf = 55                # 美股 ETF 目标比例（%）——三腿拆分的腿权重
a_share = 25               # A 股目标比例
gold = 20                  # 黄金目标比例

[thresholds]
fear = 25                  # 恐慌阈值——低于此判定"恐慌"
neutral = 45               # 中性下界
greed = 55                 # 贪婪上界——高于此判定"贪婪"
extreme_greed = 75         # 极度贪婪阈值

[buy_ratio]
# 旧框架的买入比例矩阵（仅回测对照用）
fear = 0.4
greed = 0.1

[sell_ratio]
# 旧框架的卖出比例矩阵（仅回测对照用）
fear = 0.1
greed = 0.4

[api]
fear_greed_url = "https://production.dataviz.cnn.io/index/fearandgreed/graphdata"

[target_weight]
extreme_fear = 85.0        # 极度恐慌时目标仓位（%）——逆向策略的极值
fear = 75.0
neutral = 60.0
greed = 45.0
extreme_greed = 35.0

[rebalance]
band_pp = 6.0              # 偏离带宽（百分点）——超此才动作，缓冲长期持有
min_trade_amount = 2000.0  # 最小交易额（元）
min_hold_days = 7          # 最短持有期（天）——规避惩罚性赎回费

[costs]
buy_rate = 0.001           # 买入费率
sell_rate = 0.001          # 卖出费率
cash_growth = 0.02         # 现金货币基金年化收益（回测用）
```

**关键配置解读**：

- **`target_weight`（目标仓位曲线）**：MNS 策略的数学内核。五个情绪区间各对应一个目标仓位，且必须随情绪升高单调不增（`validate` 强制，`src/config.rs:300-309`）——"越恐慌越买、越贪婪越卖"就是这条曲线。想调整攻击性，改这一组值即可。
- **`rebalance.band_pp`（偏离带宽）**：决定"什么时候需要动手"。带宽越大，持仓越稳、交易越少；带宽越小，越贴近目标、交易越频繁。默认 ±6pp 对应"多数月份不动作"的长期持有姿态。
- **`costs`（成本模型）**：回测与实盘共享同一套费率假设。`cash_growth` 让回测里的现金也按货币基金生息——回测不忽略任何一块收益，这是"成本诚实"的一部分。
- **`buy_ratio`/`sell_ratio`（旧框架矩阵）**：仅服务 `Engine::Legacy` 回测对照，不参与实盘。它们的注释已明确标注用途，防止误改。

## 数据边界与文件布局

MNS 的所有数据都留在本机，集中在两个位置：

| 路径 | 用途 | 说明 |
|------|------|------|
| `~/.mns/config.toml` | 配置文件 | 由 `mns init` 生成，`mns config` 读写 |
| `~/.mns/mns.db` | SQLite 数据库 | 5 张业务表，详见《6.数据库概览.md》 |
| `./reports/YYYY-MM-DD.txt` | 每日报告留档 | 由 `mns report` 生成，天然幂等 |
| 内置回测数据 | `include_str!` 编译进二进制 | `monthly_total_return.csv`（`src/backtest.rs:24`），零运行时依赖 |

## 集成建议

MNS 是一个单机 CLI 工具，它的"集成"更多是**流程层面的集成**：

- **定时任务（macOS launchd / Linux cron）**：每日开盘前跑 `mns update-prices` 与 `mns report`，把报告留档，收盘后看一眼 `mns market`。命令均幂等、可安全重复执行。
- **参数实验（CI 或脚本）**：用 `mns backtest run --config a.toml --compare b.toml` 批量验证参数敏感性；由于 bootstrap 使用确定性种子，同配置重复运行结果完全可复现。
- **数据备份**：只需备份 `~/.mns/` 整个目录（一个 TOML + 一个 SQLite），即可完整恢复账本与配置。
- **不宜集成**：MNS 不提供 API、无遥测、无远程服务，不适合嵌入其他系统做程序化交易——它从设计上就是"人读的参谋"，不是"机器调用的服务"。
