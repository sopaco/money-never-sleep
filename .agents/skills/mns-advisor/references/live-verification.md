# 联网核验：AGENT 的增值边界

## 定位

`~/.mns/config.toml` 里的费率、限购、结算天数、赎回阶梯是 2026-11-08 抓取的**静态假设**，会随基金公告、平台费率和额度政策变化。CLI 无法感知这些变化，AGENT 可以。这是联网能力在本项目中最有价值的用途。

联网核验的唯一合法目的是回答：**这笔已经由现金流或偏离授权的交易，今天能否按计划执行、成本与到账是否变了。**

## 核验清单

| # | 核验项 | 查什么 | 对应配置 | 不一致时 |
|---|---|---|---|---|
| 1 | 申购状态 | 是否暂停申购 / 暂停大额申购、当日限额 | `[channels.qdii_feeder].daily_subscription_cap = 520` | 保留 MNS 金额，改为分日 / 分标的排期；不改写决策 |
| 2 | 申购费率 | 平台实际折扣、是否 0 费率活动 | `[channels.*].buy_fee_pct` / `[costs].buy_fee_pct = 0.12` | 标注费用估算偏差，建议用户更新配置 |
| 3 | 赎回阶梯 | <7 日 1.5% / 7–365 日 0.5% / 365–730 日 0.25% / ≥730 日 0 是否仍有效 | `[costs].redemption_tiers` | 卖出前重新核对持有期；标注费率可能变化 |
| 4 | 赎回到账 | QDII T+7 / A 股联接 T+3 / 场内 ETF T+1 | `[channels.*].settlement_days` | 提醒在途资金不可复用，买入需顺延 |
| 5 | 标的状态 | 基金经理变更、清盘/合并、更名、跟踪指数调整、分红拆分 | `add` 建池时的标的 | 属事实变更，提示用户核对持仓池；不据此改买卖方向 |
| 6 | 交易日历 | A 股 / 美股节假日、QDII 净值披露时点、跨市场时差 | 决策日与 T+1 执行 | 顺延执行日，不新增交易理由 |
| 7 | 场内执行 | ETF 溢价、佣金、滑点 | `[channels.on_exchange_etf]` | 标注与估算偏差 |
| 8 | 现金收益 | 货币基金 / 现金管理收益率量级 | `[costs].cash_annual_yield = 1.3` | 仅影响绩效口径，不影响本次买卖 |

## 来源要求

- 优先基金公司公告、基金销售平台产品页、交易所与指数公司公告；标注查询日期。
- 对同一事实尽量取两个独立来源；取不到时明确写「未核实」，不要用推测填空。
- 自媒体观点、研报评级、论坛情绪**不作为事实来源**，也不进入决策卡的依据栏。
- 每条核验结果保留可复查的出处描述（站点 + 页面 + 日期），不写「据网上说」。

## 事实与推断分离

- **事实**：公告写明的限购额度、费率、交易日、基金状态。
- **MNS 计算**：目标权重、偏离、金额、年度笔数、XIRR、回撤。
- **推断**：把事实映射到执行排期（例如「¥520/日 → 需 3 个交易日」）。
- **用户陈述**：金额、用途、时间约束、主观想法。

四类信息在决策卡中分栏，不合并成一段叙述。不要把推断写成事实，不要把用户的主观判断写成 MNS 的结论。

## 合法用途与禁止用途

| 合法 | 禁止 |
|---|---|
| 判断今天能否下单、是否需要分日 | 用宏观新闻判断该不该买 |
| 核对实际费率与到账天数 | 用研报评级调整目标仓位 |
| 发现标的暂停申购 / 清盘风险 | 用「市场情绪转好」覆盖 `effective_score` |
| 发现配置假设过期并提示更新 | 用联网信息构造新的择时信号 |
| 提示节假日与净值披露时点 | 把「利好/利空」写进决策卡依据 |

## 配置更新纪律

发现配置与现实不符时：

1. 在决策卡中标注「MNS 计算基于 YYYY-MM-DD 的旧假设，本次金额需人工复核」。
2. 给出建议的命令（如 `mns config costs.buy_fee_pct 0.08`；通道与阶梯参数需直接编辑 `~/.mns/config.toml`）。
3. 等用户确认后再改，不自动执行。
4. 提醒：`[target_weight]` / `[rebalance]` / `backtest.decision_interval` 是实盘与回测同源参数，改它们会同时改变 `mns report` 与 `mns backtest` 的口径，不属于「执行核验」范畴，需单独说明理由。
